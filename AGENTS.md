# Working on Master Roller

- Read the assigned GitHub issue and its dependencies first. Use a branch and PR per new ticket; reference the issue and provide validation evidence.
- The game is a static React/TypeScript/Vite app deployed under `/master-roller/` on GitHub Pages. Preserve project-relative asset loading.
- Rules and balancing constants belong in `src/game.ts`. Keep the engine pure and randomness injectable. React manages presentation, animation and saving.
- Start with one d4 in one slot. Supported dice are d4, d6, d8, d10, d12, d20 and d100, each rolling 1 through its face count. All owned dice roll together. A sum at least the level wins and advances exactly one level. Every roll earns its total in Dicecoin. Each extra slot doubles the next slot’s price (3, 6, 12… Dicecoin). Each paid purchase doubles that die type’s next price, using persistent per-type purchase counts; owned dice cannot exceed slots. Change these only when the assigned task requests it.
- Merges are free and consume two owned dice whose maximums sum to a supported die’s maximum, granting one copy of that die and freeing one used slot. Keep purchased slots, balance and level; clear obsolete last-roll history. Derive recipes from DICE in src/game.ts and validate required copy counts. Economy timing simulations are buy-only and do not merge.
- Purchases in the Test Lab are simulated and must clearly say no charge. There is no billing backend.
- Preserve the versioned save contract or provide an explicit migration. Version 3 adds lifetime paid purchase counts; free grants and merges must not reset/increment them. Valid v1/v2 saves migrate by inferring existing copies excluding the starter d4, retaining progress and backing up the source before replacement. Version 1 also upgrades d2/d3 to d4, grants capacity and clears obsolete last-roll history; v2 history stays intact. Failed backup must prevent overwriting the original. Invalid saves must not be silently overwritten.
- Economy-lab prices are drafts stored separately from game saves. Keep its simulations pure, seeded, and explicit about strategy, slot costs, sample size and capped/unreached runs.
- Use Node.js 24+. Install with `npm ci`; install Chromium with `npx playwright install chromium` (CI also needs `--with-deps`). Run `npm run gate` before completing changes that affect gameplay or release behavior.
- Tests live in `tests/unit` and `tests/browser`. Progression reports come from `npm run simulate`. Avoid changing prices just to satisfy a test or simulation.
